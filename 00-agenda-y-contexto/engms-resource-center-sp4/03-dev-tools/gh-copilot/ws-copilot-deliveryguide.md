# Delivery Guide: Workshop - GitHub - Copilot for Business Fundamentals
This guide will provides details and instructions to help you deliver the **Workshop - GitHub - Copilot for Business Fundamentals** for your customer. 
This engagement must accomplish the following objectives:  

**Objectives**
After completing this training, learners will be able to:

- Understand the benefits and how to start using GitHub Copilot
- Understand how to write code faster
- Stay in the development flow longer for the solution
- Focus on the Business use case and Problem Statement

After this engagement, your team will be able to:

- Reduce time spent on repetitive tasks
- Reduce time spent on boilerplates
- Limit context switching between different tools
- Improve the developer experience

**Deliverable Standards**
Education session containing instructor sessions with slides, demos, and hands on labs.

## Customer Participants

Having the right customer participants in the  workshop is essential to completing a successful engagement. 
Ensure the customer roles outlined below are available and able to participate in the workshop. 

- Developers
- Team Leads
- Development Leaders
- Project Managers

## Delivery Guidance
This section includes all non-technical delivery guidance and supporting artifacts for this delivery. 
You are free to adapt each step to meet your customers needs as long as you are able to meet the objectives and deliverable standards for next MCEM phase. 

### Step 1: Preparing for the delivery

- You have reviewed the training outline and objectives as described in the slide deck available on the IP Share
  - the slide deck contains speaker notes for each topic
  - review the [demo repo](https://github.com/ps-copilot-sandbox/copilot-fundamentals-training) used for the presentation
  - The slide deck along with slide deck demos and attendee follow along is approximately 4 hours of content.  You can share the MOAW lab as self-guided content for the attendees to complete after the session if they want to practice more.  Or you can incorporate the lab into the same session.
  - The IPShare also contains additional resources such as enablement decks and videos

- You have informed the customer about the training pre-requisites. In this case, if they'd like to follow along with demos or complete any of the hands-on exercises, GitHub Copilot for Business must be enabled on the supported target platforms.

- Gain access to [GitHub Copilot](https://aka.ms/copilot) for your work and personal account 
- Gain access to the [GitHub demo environment](https://microsoft.sharepoint.com/:w:/r/teams/GithubSales/_layouts/15/Doc.aspx?sourcedoc=%7B264B191D-9345-4393-8A4C-63D73DFD0B49%7D&file=Onboarding%20Microsoft%20Users%20to%20the%20EMU.docx&action=default&mobileredirect=true).
- Gain access to demo scripts on [GH Sales](https://microsoft.sharepoint.com/teams/GithubSales/SitePages/Sales-Tools.aspx) that will help you complete the demos mentioned in the slide deck

- If delivering the lab day...
   - You have reviewed the [Github Copilot Workshop on MOAW](https://moaw.dev/workshop/gh:Philess/GHCopilotHoL/main/docs/) which will be used for the hands-on labs

### Step 2: Scoping

Explain how the delivery will be carried out. What the customer can expect at each phase, before and after delivery. 
Make sure the right stakeholders from the customer's organization are present throughout the delivery. Refer to [Customer Participants](#customer-participants) section for details.

Ensure you discuss and understand the customer's requirements and that the tooling to be used is agreed. 
Ensure all the stakeholders are on the same page regarding the deliverables and outcomes.

If you are delivering the lab component or if the customer is planning to follow along with any demos, please help them better understand the pre-requisites to set up before the day of the delivery.
You can point them to relevant documentation or recommend a proof-of-concept VBD activity, if they require help.

### Step 3: Kickoff

Share details of what workshop activities you will cover and what will not be covered. 
If a specific topic of interest is not covered, then you should have already thought about handling it during or after scoping.
However if you can accomodate last minute request, we recommend you do so to achieve a greater level of customer satisfaction with the offering.

### Step 4: Delivery

Customers can choose one module per workshop day for this delivery. 
If there is extra time after the core content has been completed you may pick optional topics from another module.
Alternatively you may also choose to add additional guided demos or an extended Q&A to the agenda. 
Utiltize the resources on the GitHub Sales SharePoint (linked below) to access the latest version of the GitHub Copilot FAQ.

Ensure you cover modules that are relevant to or identified for the success of the VBD activity.

In order to keep focus and ensure that the customer gets as much as possible out of the training, please ensure the items below are completed.

-  Make sure the customer understands that all participants need a GitHub account on the supported target platform with their corporate login and GitHub Copilot enabled.
-  **Introduction** of participants and providers
-  Give a reminder that the enablement will be performed on the recent version of Copilot and Copilot Chat
-  Present and discuss the **learning objectives slide** and the **agenda**
-  Do the ice breaker for each training day to get to know the audience, encourage interactions, and learn expectations
-  For each section in the slide deck, ensure that the following items are covered:
   - A thorough, clear presentation of the content covered in the slides (don't forget the **speaker notes**)
   - While it is not mandatory for the customer to complete the Demos, we give them the opportunity to follow along if they would like. Give the audience enough time to complete the hands-ons. Have them write to the chat if they are done or have any questions
   - Demo the hands-on yourself to make sure nobody was lost and could not follow along
   - Questions raised by the audience, either via chat or verbally, have been either addressed directly or noted for follow-up
-  Do a retro at the end of each day to collect feedback and manage the expectations
-  Once the session is done, do a final Q&A to collect any questions not addressed during the training

#### Module 2: Copilot Hands-on Lab Delivery (optional)

`Note: Module 1 is approximately 4 hours long by itself and it includes option for the customer to follow along with demos. If you are delivering the lab day, please ensure that the customer is aware that the lab is an additional activity and will take more time.`

Ensure you cover modules that are relevant to or identified for the success of the VBD activity.
When delivering the lab day you may choose to augment the topics with theory content from the slide material available on the IPShare or the GitHub Sales SharePoint.

The activities proposed in the lab can be chosen based on the customer's requirements and the time available for the lab. 
The goal of this module is to help developers understand how to use GitHub Copilot for Business in their day to day routine.

The challenges and labs can be used to test their ability to apply the knowledge gained from the guided parts. 
As part of your prep work for this module you should complete the activities at least once in your own time before delivering.

##### GitHub Copilot Workshop - MOAW.dev

The first part of this workshop are guided labs. This is followed by challenges that are not guided. 
The challenges can be made optional if needed.

The full activity with the challenges will take around 3 to 4 hours to complete. 
You may decide to demo some of the challenge solutions in greater detail and encourage discussion from the customer. 

`Note: The GitHub Copilot for Business service, with its different use cases and integrations rapidly evolves over time, so the hands-on lab will evolve along with it. Feedback and PRs to the lab content are always welcome to improve the offering.`

The workshop instruction are available publicly on [aka.ms/github-copilot-hol](https://aka.ms/github-copilot-hol) 
Share the url with the customer and ask them to follow the instructions to complete the lab. 

`Note: The lab is created to be run on VS code or Github Codespaces, but it can be adapted to be run on any IDE that supports GitHub Copilot. Be sure that you can provide support for the customer scenario, as the plugin can have small differences between different IDEs and versions.`

Here are the main topics covered in the content:
  - Setup: pre-requisites & configuration instructions
  - GitHub Copilot completion
  - Copilot chat
  - Copilot edit & agent mode
  - Copilot Advanced techniques

#####  Mastering GitHub Copilot for AI Paired Programming  - Microsoft organization on GitHub

This option is a publicly available 6-lesson course teaching everything you need to know about harnessing GitHub Copilot and an AI Paired Programing resource.
Participants should fork the repo to start working through the workshop content. 

[The repo](https://github.com/microsoft/Mastering-GitHub-Copilot-for-Paired-Programming) contains slides for each topic (in the PDF format) that you are encouraged to present before participants start working through the hands-on activities.
If covering all modules the workshop may run somewhat longer than a day. You should therefore select the content that is most appropriate for the customer and reasonable to complete in the time avaialble.

The workshop covers AI-driven coding assistance through GitHub Copilot, empowering students to accelerate their coding skills in tandem with a partner. 
It allows participants to dive deep into GitHub Copilot's autocompletion, customizable features, and advanced programming techniques, all while embracing AI-driven algorithms. 

From error handling to unit testing, the curriculum is tailored to instill best practices and enhance code quality. 

Here are the main topics covered in the content:
  - Introduction to GitHub
  - Introduction to GitHub Codespaces
  - Introduction to GitHub Copilot
  - Harnessing GitHub Copilot with JavaScript
  - Harnessing GitHub Copilot with Python
  - Creating a Mini Game with GitHub Copilot
