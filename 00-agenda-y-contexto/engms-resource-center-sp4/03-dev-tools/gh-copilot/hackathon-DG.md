# Delivery Guide: Accelerate your development with GitHub Copilot Hackathon
This guide provides details and instructions to help you deliver a Hackathon engagement for GitHub Copilot. 
It outlines the steps prior to, during, and after the engagement, to help you keep track of the key deliverables and action items. 

## Description
A Hackathon is an event run over a relatively short time frame, where people get the chance to collaborate in a focused way on a set of use cases, challenges, or initiatives that are deemed interesting to the participants. The goal of a Hackathon is not only to work on solutions, but also to facilitate better collaboration (often across teams and departments), team building, and innovation.

**Objectives**

A GitHub Copilot Hackathon engagement is intended to help customers achieve the following:

- Create momentum and excitement around their GitHub Copilot adoption
- Enhance internal competencies of GitHub Copilot features
- Showcase how GitHub Copilot can help improve the developer workflow in real scenarios

**Deliverable Standards**

## Customer Participants

The engagement is designed for up to 100 participants.
Deliveries in smaller groups are possible and should be scoped appropriately.

- Developers
- Event sponsor(s) / Leaders
- Development Leaders
- Engineering Managers
- Executive Sponsor(s)

## Delivery Guidance
This section includes delivery guidance and supporting artifacts.  
You are free to adapt each step to meet your customers needs as long as you are able to meet the objectives and deliverable standards. 

### Step 1: Scoping

Before the Hackathon event starts, conduct a scoping call to confirm the following requirements:

- Is there any customer-specific context with right to the Hackathon that needs to be captured or reviewed?
  - Examples:
    - Expected number of attendees
    - Existing hackathon process at customer (if any)
    - On-site VS remote delivery
    - Desired duration
    - Any other requirements that impact the standard hackathon agenda
- A sufficient amount of GitHub Copilot licenses are in place ot cover all Hackathon attendees
- Sourcing and documentation of the hackathon use case
    - In most cases it is beneficial to source potential use cases ahead of the Hackathon day itself to free up more time for hands-on work and give attendees enough time to think of interesting challenges
    - Some customers might prefer to curate a pre-selected list of use cases on behalf of the attendees. If so, make sure to get an overview of these.
- Full list of attendee names and emails collected (if available)
- An agenda is circulated to all attendees (in most cases circulated by a point-of-contact on customer side)
- GitHub Account Manager and/or the GitHub Customer Success Manager (CSM) to arrange any Swag to be handed out during the Hackathon
    - Find their details in OctoDash via [https://aka.ms/OctoDash](https://aka.ms/OctoDash)
    - Check first with the customer if they are interested
    - Swag delivery can take considerable time to arrange, ensure that you reach out the the Account Manager and/or the CSM as early as possible
- If delivering on-site, ensure that travel arrangements are done in accordance with the applicable guidelines and that access to on-site venue is arranged with customer

Some organization already host Hackathons on a regular basis and therefore already have a well-tested framework for running these events. Thus, the format of this module can differ between customers in terms of duration, number of attendees, and the overall process. Any such customer-specific needs that fall outside of the default structure of this module should be captured during the pre-sales / scoping process.
Assuming that there are no customer-specific modifications needed, the high-level outline of the GitHub Copilot Hackathon is as follows;

- **Duration:** 8 hours / 1 day incl. breaks
   - Optimally this is delivered on the same day
- **Agenda:**
   - Introduction (~30min)
     - Facilitators
     - Team overview
     - Use cases
     - (any customer-specific messaging)
   - GitHub Copilot presentation / Q&A (~30min)
   - Hacking (~5 hours) incl. lunch break
   - Team presentations (~45min)
   - Roundtable discussion / Q&A / WrapUp (~30min - 1 hour)
- **Remote/onsite:** As agreed with customer

### Step 2: Delivery

During the Hackathon itself, ensure that these tasks are completed:

- All presentations / agenda items are presented and completed as per the plan agreed upon with the customer
- All teams / attendees have chosen / been assigned to a use case
- All attendees have access to the tooling they need for the Hackathon (customer responsibility)
- The provider is available (on-site or remote) throughout the Hackathon for any support needed by the Hackathon attendees
- All teams / attendees have presented their results to the broader group
    - This can be skipped in case the number of attendees is so large that it does not fit into the allotted time. For example, if there are 30 teams and each get 5 minutes to present then that will consume at least 2.5 hours.
    - Make sure this is discussed with the customer up front.

### Step 3: Close Out and Follow Up


When closing out the delivery, please remember to:

- Ensure all questions that were not addressed during the Hackathon directly are followed up on
- Like with any other Unified delivery your main customer contact may receive an automated survey for this engagement. Ensure that their contact details are correct before closing your dispatch. 
- Ensure all of your time has been recorded in ESXP 
- Discuss with the Account Team, Regional GitHub Director and/or GitHub Engagement Manager about creating a customer story for the delivery of the engagement
    - This might be of interest in case the Hackathon is delivered as a standalone engagement and e.g. there were a large number of attendees
