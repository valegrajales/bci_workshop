# Delivery Guide: Workshop - GitHub - Copilot for Developers Intermediate
This guide will provides details and instructions to help you deliver the **Workshop - GitHub - Copilot for Developers Intermediate** for your customer. 
This engagement must accomplish the following objectives:  

**Objectives**

After completing this training, developers will be able to:

- Integrate key features of GitHub Copilot in their daily work
- Write code faster and with less context switching
- Improve the developer experience and reduce context switching
- Focus more time on important tasks instead of boilerplate
- Apply context/prompt engineering best practices for better suggestions
- Leverage Copilot coding agent with MCP (Model Content Protocol)
- Onboard onto a new, unfamiliar codebase with less effort

## Delivery Guidance
This section includes all non-technical delivery guidance and supporting artifacts for this delivery. 
You are free to adapt each step to meet your customers needs as long as you are able to meet the objectives and deliverable standards for next MCEM phase. 

### Step 1: Preparing for the delivery

- You have reviewed the training outline and objectives as described in the slide deck available on the IP Share
  - the slide deck contains speaker notes for each topic
  - The IPShare also contains additional resources such as enablement decks and videos

- You have reviewed the [demos](https://github.com/ps-copilot-sandbox/copilot-intermediate-gallery-repo) associated with this delivery. 

- You have informed the customer about the training pre-requisites. 
  - For this delivery to be successful, GitHub Copilot must be enabled on the supported target platforms, and participants must either have GitHub Copilot Business or Enterprise license. 

- Gain access to the [GitHub demo environment](https://microsoft.sharepoint.com/:w:/r/teams/GithubSales/_layouts/15/Doc.aspx?sourcedoc=%7B264B191D-9345-4393-8A4C-63D73DFD0B49%7D&file=Onboarding%20Microsoft%20Users%20to%20the%20EMU.docx&action=default&mobileredirect=true)
- Gain access to [GitHub Copilot](https://aka.ms/copilot) for your work and linked personal account

- [Review the GitHub Copilot "Getting Started" resources](https://github.com/features/copilot/getting-started)
- [Review GitHub Copilot usage guidance by the Cloud Advocacy team](https://repos.opensource.microsoft.com/orgs/MicrosoftCopilot?section=videos#vscode)

### Step 2: Scoping

Explain how the delivery will be carried out, and what the customer can expect at each phase, before and after delivery. 
Make sure the right stakeholders from the customer's organization are present throughout the delivery.

Ensure you discuss and understand the customer's requirements and that the tooling to be used is agreed. 
Ensure all the stakeholders are on the same page regarding the mode of delivery, the deliverables and the outcomes of the delivery.

### Step 3: Kickoff

Share details of what workshop activities you will cover and what will not be covered. 
Any agenda changes should already have been discussed during scoping, but the kickoff meeting is an opportunity to make any last minute changes and maximize customer satisfaction.
At this stage you are not required to make accomodations that aren't feasible. You should however consider anything that gets raised.

### Step 4: Delivery

-  Make sure the customer understands that all participants need a GitHub account on the supported target platform (IDE) with their corporate login and GitHub Copilot (Business or Enterprise license) enabled.
-  **Introduction** of participants and providers
-  Give a reminder that the enablement will be performed on the recent release version of GitHub Copilot and Copilot Chat
-  Present and discuss the **agenda**
-  Do the ice breaker for each training day to get to know the audience, encourage interactions, and learn expectations
-  Complete the outcome of this training
   -  Give customer answers to specific use case scenario questions
   -  Increase existing GitHub Copilot skill by following specific workshop tutorial catered to their need
   -  Teach in-depth tips and tricks, best practices on how to best utilize GitHub Copilot
-  For each section in the slide deck, ensure that the following items are covered:
   - Provide an introduction to GitHub Copilot. This would include answering questions such as 'What is GitHub Copilot', supported IDEs, the requirements and data flow.
   - Show the features of GitHub copilot to increase the developer productivity with coding.
   - Explain best practices with prompt/context engineering to enhance coding suggestions offered by GitHub Copilot.
   - Explain how to switch between the AI models, leverage custom instructions, and reusable prompt files. 
   - Provide an introduction to Copilot Spaces that can help with creating shared, goal-focused workspaces so Copilot stays grounded.
   - Explain how Copilot agent can automate tasks end-to-end and how its functionality can be extended using MCP.
   - Provide an opportunity for the participants to apply the learning using hands-on workshop and showcase the outcome.
   - Questions raised by the audience, either via chat or verbally, have been either addressed directly or noted for follow-up.
-  Do a retro at the end of each day to collect feedback and manage the expectations.
-  Once the session is done, do a final Q&A to collect any questions not addressed during the training.

The following agenda items should be covered during the workshop:
-  GitHub Copilot Introduction
   - Introduction
   - Learning Objectives
-  GitHub Copilot Features
   - IDE Features
   - Choosing the Right Model
-  GitHub Copilot Prompt/Context engineering
   - Data Flows
   - Context Engineering
   - Prompting Techniques
-  Customizing GitHub Copilot
   - Premium Requests
   - Custom Instructions/ Prompt Files
-  Model Context Protocol (MCP)
   - Overview
   - Core Concepts
-  GitHub Copilot Spaces
   - Creating Spaces
   - Team Collaboration
-  GitHub Copilot coding agent
   - Agent Mode vs Coding agent
   - Architecture
-  Coding agent with MCP
-  Hands-on workshops
-  Cover questions from the customer

### Step 5: Customer close out

If needed send follow up materials / resources to the attendees. 
Ensure that the customer understands what the next steps are after the workshop activities. 
You need to understand the basics of VBD (such as survey procedures) and tell them what they can expect next. (in terms of communication from the CSAM or the account team)
