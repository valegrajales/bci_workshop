# Delivery Guide: Architecture Design and Review Session for AI Apps and Agents

This guide will provide details and instructions to help you deliver a successful Architecture Design (ADS) or Architecture Review Session (ARS) for your customer.

## Objectives

- Understand the customer’s business goals and review current architecture and workloads to identify architectural gaps and improvement areas.
- Technology selection: Map business requirements to Microsoft Foundry, Azure AI services, Azure AI Agent Service, Microsoft Copilot Studio, Microsoft 365 Copilot, and supporting frameworks and patterns.
- Analyze app and data workloads and dependencies such as interfaces, existing applications, and their current architecture to support modern Azure AI integration.
- Identify and assess infrastructure readiness for an AI workload and recommend improvements for scalability, resilience, and security.
- Apply Azure Monitor, Application Insights, and AI workload observability best practices for performance tracking and proactive issue resolution.
- Review responsible AI and safety capabilities such as Content Safety, Prompt Shields, grounding quality, and evaluation workflows.
- Apply Agentic DevOps and code security practices and concepts

### For an Architecture Design Session delivery

This session aims to establish a well-defined strategy for incorporating Azure AI capabilities into a customer’s solution by aligning with their business objectives, evaluating existing architectural frameworks, and analyzing current workloads to ensure seamless integration, operational readiness, and optimal performance.

### For an Architecture Review Session delivery

This session serves to validate and refine the architecture post-PoC or Pilot, ensuring alignment with production requirements and scalability. Insights gained will inform deployment strategies and be shared across relevant teams to facilitate a smooth transition to full-scale implementation.

## **Microsoft AI Solutions**
There are many ways that developers can create AI apps and agents, including multiple frameworks and SDKs.

### [Microsoft Foundry](#tab/Microsoft-Foundry)
Microsoft Foundry is the primary developer platform for designing, evaluating, and operating custom AI apps and agents on Azure. It is best suited for code-first solutions that need flexible model choice, enterprise security boundaries, grounding with enterprise data, evaluation workflows, and integration with Azure services. It also provides a unified experience across model catalog, prompt flow, tracing, evaluations, and deployment management.

### Architecture Design Review Checklist

The following are the Architecture Design Review Checklist items for Microsoft Foundry.

1. Ensure the Microsoft Foundry architecture is designed with a clear separation between the Foundry resource for centralized governance and Foundry projects for isolated AI development and deployment.

2. Validate that the appropriate AI model(GPT,embeddings, or fine-tuned model)is selected and properly configured.

3. Confirm the data sources and storage services are clearly defined with secure and reliable ingestion pipelines.

4. Access to AI resources is governed through role‑based access controls, ensuring clear accountability, separation of duties, and adherence to least‑privilege principles.

5. Network and data boundaries are explicitly defined to protect sensitive enterprise data and prevent unintended data exposure or exfiltration.

6. Security monitoring and alerting are enabled to provide continuous visibility into AI‑related risks and threats.

7. Confirm CI/CD Pipelines and Infrastructure as Code (Terraform/Bicep) are used with proper enivironment seperation.

8. Verify reliabilty mechanisms such as retrypolicies, timeout handling, fallback responses and error management.

### Architecture Design Review Checklist

The following are the Architecture Design Review Checklist items

1. Confirm the business objectives, success criteria, and expected outcomes that the target architecture must support.

2. Review the current‑state architecture to identify constraints, dependencies, and risks that influence the target design.

3. Define the proposed target‑state architecture, including major components, integrations, and system boundaries.

4. Validate non‑functional requirements such as security, reliability, performance, scalability, and compliance that the architecture must address.

5. Review identity, access control, and security design to ensure alignment with enterprise security and governance principles.

6. Assess resiliency and reliability considerations, including failure handling, recovery expectations, and operational continuity.

7. Evaluate operational aspects of the architecture, including monitoring, deployment, observability, and support model.

8. Capture key architectural decisions, assumptions, risks, and open questions, and agree on next steps to de‑risk the solution before implementation.

##### Agentic Chat vs Multi-Agent System vs Multi-Agent Orchestration

A key question to address early in the engagement is whether the customer is building an agentic chat experience, a multi-agent system, or a multi-agent orchestration pattern. The following bullets will guide you when selecting the appropriate pattern:

- Agentic Chat: Best for intelligent, task-aware conversational interfaces.
- Multi-Agent System: Ideal for distributed, autonomous problem-solving.
- Multi-Agent Orchestration: Best for structured, coordinated workflows across agents.

The following tabs will help you decide which solution is more suitable for the customer use case.

### [Agentic Chat](#tab/Agentic-Chat)

There are multiple options for implementing agentic chat solutions. The most common are Azure AI Agent Service, Semantic Kernel, AutoGen, LangChain, or direct use of Azure OpenAI APIs with your application runtime. Semantic Kernel remains a strong enterprise option because it is production-ready and supportable for customers that need a Microsoft-backed SDK and orchestration layer.


Select this option when:

- User Interaction: Primarily conversational with light task execution.
- Autonomy: Low to moderate; single agent handles tasks.
- Complexity: Suitable for simple or linear workflows.
- Integration: Limited to a few APIs or services.
- Scalability: Designed for single-agent use cases.
- Speed to Deploy: Fast to implement and iterate.
- User Experience: Unified, consistent persona.


### [MultiAgent System](#tab/MultiAgent-System)

This may also be a good time to evaluate whether [Azure AI services](https://azure.microsoft.com/en-us/products/ai-services/#Services-and-models), Microsoft Foundry, or Azure AI Agent Service can address some or all of the customer business needs, or if the customer requires a more customized platform architecture.


Select this option when:

- Agent Independence: Each agent has its own logic and goals.
- Problem Domain: Complex, requiring specialization.
- Coordination: Decentralized or loosely coupled.
- Adaptability: High; agents can evolve or learn independently.
- Scalability: High; supports horizontal scaling.
- Emergent Behavior: System behavior arises from agent interactions.

  - Multi-instance deployment needs
